# EXP-001 — Baseline ORB on GC=F, in-sample archive

Status: **draft — waiting for Nick's approval of the criteria. Not run.**

## Hypothesis
A 15-minute opening-range breakout at the NY open on gold (GC=F prices, traded as Micro Gold)
has a positive expectancy per trade after realistic costs, with the rules and numbers fixed in
Stage C *before* any trade result was seen.

## Setup
- Setup: `orb` only (momentum stays disabled).
- Primary: GC=F (sized and charged as MGC). Cross-check: GLD with its own costs.
- Variants: news guard as configured (open guard 30 min on CPI/NFP days) and off; costs x0,
  x1, x2. That is 2 symbols x 2 guard variants x 3 cost levels = **12 trials**, all logged in
  `experiments/trial_log.csv`. No parameter grid in this experiment.

## Exact parameters
Strategy hash `219b8dfb9257` (covers instruments, session, risk, news guard, setups, costs,
execution, analysis windows). ORB: or_minutes 15, k 2.0, stop_fraction 1.0, range filter
0.10–0.60 x ATR(14 daily, from 1h bars), volume >= 1.2 x the same-time average of the last
10 sessions (at least 5 present), entry = next bar open after a 5m close beyond the range,
last signal bar closes by 11:30 ET, 1 signal per day. Session 09:30–12:00 ET. Risk 0.5 % of
$100k per trade, position value <= 1x capital, max 2 trades/day, 3 stops end the day, daily
loss limit 1.5 %. Costs: docs/cost_model.md.

## Data window
In-sample: 2026-09-11 .. 2026-11-06 (config `analysis.in_sample`), 5-minute archive.
About 41 trading days; the first days have no volume profile yet. Stage C signal counts
(`reports/signals/orb_GC_F_2026-11-09_signals.csv`): 27 signals on GC=F, i.e. **fewer than
30 trades are expected**. The out-of-sample window (from 2026-11-09) is NOT touched.

## Success and failure criteria (written before running)
Evaluated on GC=F, news guard as configured, costs x1, 95 % bootstrap CI (10 000 resamples,
seed 20261109):
1. Fewer than 30 filled trades -> **INCONCLUSIVE (insufficient sample)**, whatever the numbers.
2. CI lower bound > 0 R **and** mean R net at costs x2 > 0 -> **SUCCESS**.
3. CI upper bound < 0 R -> **FAILURE**.
4. Anything else -> **INCONCLUSIVE (no demonstrated edge)**.

Given rule 1 and ~27 expected trades, the most likely outcome is INCONCLUSIVE. That is
accepted in advance: the purpose of EXP-001 is to fix the baseline, check the pipeline on real
data and measure costs in R. The real test is the forward out-of-sample data (Stage F).

What each outcome leads to:
- SUCCESS -> no parameter change; forward paper test with exactly these rules; a later
  experiment opens the OOS window once there are >= 30 forward trades.
- FAILURE -> ORB baseline is frozen (`enabled: false`, commit message references EXP-001);
  re-enabled only through a new experiment.
- INCONCLUSIVE -> no parameter change; keep forward-testing these exact rules; decide on the
  OOS window once >= 30 forward trades exist.
- In every case GLD and the guard-off / cost variants are reported but do not change the
  decision.
